# Починка селекторов ufc.com

Вёрстка ufc.com меняется несколько раз в год. Это самая частая поломка в проекте,
и чинится она правкой одного списка констант — не переписывайте парсер целиком.

## Когда применять

- `make events` пишет «Ничего не найдено» или «боёв загружено — 0»;
- бойцы появляются в базе, но без статистики (`data_completeness` низкая);
- в `backend/storage/logs/scraping-*.log` есть «вероятно, изменилась вёрстка ufc.com»
  или «Не удалось разобрать карточку бойца».

## Порядок действий

### 1. Убедиться, что дело в вёрстке, а не в сети или кэше

```bash
make logs                       # ошибки Guzzle, таймауты, коды 403/503
docker compose exec php php artisan tinker --execute="echo \App\Models\ScrapeLog::latest('fetched_at')->first()?->toJson();"
```

Смотрите поля `status`, `http_status`, `error`, `response_bytes`:

- `status = failed` — проблема с сетью или доступом, селекторы ни при чём;
- `status = skipped` — запрос запретил `robots.txt`;
- `status = ok` и разумный `response_bytes`, но данных нет — **это наш случай**;
- маленький `response_bytes` (несколько килобайт) — скорее всего отдали заглушку
  или страница целиком рисуется скриптами.

Кэш держит страницу 24 часа. Чтобы перечитать её принудительно, добавляйте `--force`:

```bash
docker compose exec php php artisan ufc:sync-events --fights --force
```

### 2. Посмотреть, что реально пришло

Тело ответа сохраняется в `scrape_logs.body` — доставать страницу заново не нужно:

```bash
docker compose exec php php artisan tinker --execute="
  \$log = \App\Models\ScrapeLog::where('source','ufc')->where('status','ok')->latest('fetched_at')->first();
  file_put_contents('/tmp/page.html', \$log->body);
  echo \$log->url;
"
docker compose exec php sh -c "grep -o 'class=\"[^\"]*card[^\"]*\"' /tmp/page.html | sort -u | head -30"
```

Параллельно откройте нужную страницу в браузере и посмотрите в инспекторе
фактические классы:

- список турниров — https://www.ufc.com/events
- карточка бойца — https://www.ufc.com/athlete/<slug>

### 3. Поправить константы

Все селекторы собраны наверху двух файлов. Больше нигде их нет.

**`backend/app/Services/Scraping/UfcEventScraper.php`**

| Константа | Что ищет |
|---|---|
| `EVENT_CARD_SELECTORS` | карточка турнира в списке |
| `EVENT_LINK_SELECTORS` | ссылка на страницу турнира внутри карточки |
| `EVENT_DATE_SELECTORS` | дата турнира |
| `FIGHT_SELECTORS` | блок одного боя на странице турнира |

Селекторы имён бойцов, весовой категории и признака титульного боя находятся
в методе `parseFightNode()` — там же запасной вариант, когда имя и фамилия
разнесены по разным элементам.

**`backend/app/Services/Scraping/UfcFighterScraper.php`**

| Метод | Что разбирает |
|---|---|
| `parse()` | прозвище, изображение, категория, рекорд |
| `parseBio()` | блок «биография»: рост, размах, возраст, стойка |
| `parseWinMethods()` | разбивка побед на KO / сабмишен / решение |
| `parseCareerStats()` | удары в минуту, точность, тейкдауны, защита |

Подписи полей биографии сопоставляются через `BIO_FIELDS` — если UFC переименует
подпись, добавьте новый ключ туда, а не в код разбора.

**Правила правки:**

- каждая константа — массив: перечисляйте несколько вариантов селектора,
  парсер пробует их по очереди и берёт первый непустой;
- старые варианты не удаляйте, добавляйте новые в начало списка — так парсер
  переживёт откат вёрстки;
- разбор должен оставаться «мягким»: используйте помощники `Dom::text()`,
  `Dom::attr()`, `Dom::texts()`, которые возвращают `null` вместо исключения;
- ничего не хардкодьте вне констант.

### 4. Проверить

```bash
docker compose exec php php artisan ufc:sync-events --fights --force
docker compose exec php php artisan ufc:sync-fighters --force
make logs
```

Затем убедитесь, что данные доехали:

```bash
docker compose exec php php artisan tinker --execute="
  echo \App\Models\Event::count().' турниров, '
      .\App\Models\Fight::count().' боёв, '
      .\App\Models\Fighter::whereNotNull('stats_updated_at')->count().' бойцов со статистикой';
"
```

Пересчитайте прогнозы и посмотрите, что полнота данных выросла:

```bash
make predict
```

В интерфейсе на странице боя должно исчезнуть предупреждение
«статистика заполнена лишь на N%».

### 5. Обновить парсинг помощниками `Dom`, если поменялся формат значений

Форматы вроде `5' 11"`, `76.0`, `4:35`, `18-3-1 (1 NC)`, `KO/TKO` разбираются
в `backend/app/Services/Scraping/Dom.php`. Если UFC сменит формат, правьте там
и обязательно добавьте случай в `backend/tests/Unit/DomTest.php`:

```bash
make test-unit
```

## Если страница рисуется скриптами

Признак: `status = ok`, но в теле нет ни имён бойцов, ни статистики — только
каркас и теги `<script>`. Тогда HTML-парсер бессилен, и варианты такие:

1. поискать в теле встроенный JSON (`window.__NUXT__`, `application/ld+json`,
   `data-drupal-selector`) — часто все данные лежат там, и разбирать надо его;
2. взять данные из Sherdog (`config('ufc.sources.sherdog')`, парсер уже есть
   в `ResultsScraper::fromSherdog`);
3. оставить ручной ввод — интерфейс это полностью поддерживает.

Headless-браузер в проект не добавляйте без явной просьбы владельца: это тянет
тяжёлую зависимость в контейнер ради задачи, которая решается ручным вводом.

## Чего не делать

- Не убирайте проверку `robots.txt` и не уменьшайте паузы между запросами —
  это требования раздела 2 ТЗ (`config/ufc.php`, ключ `sources`).
- Не обходите `HttpFetcher` прямыми вызовами Guzzle: потеряются кэш, лимиты и журнал.
- Не отключайте кэш насовсем — пользуйтесь флагом `--force` точечно.
