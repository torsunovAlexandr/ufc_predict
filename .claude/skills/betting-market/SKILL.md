# Добавление нового рынка ставок

Рынок затрагивает семь мест. Пропуск любого приводит к тихой поломке: ставка либо
не появится, либо появится и никогда не рассчитается, повиснув в статусе «размещена».

Существующие рынки: `moneyline`, `draw`, `totals`, `method`. Значение хранится в паре
колонок `market` + `selection`, при необходимости с числовой `line`.

## Чек-лист

### 1. Схема БД

`market` — это `enum` в трёх миграциях: `odds`, `bets`, и он же используется в валидации.
Если добавляете новое значение `market` (а не новый `selection` внутри существующего),
нужна миграция:

```php
Schema::table('odds', function (Blueprint $table) {
    $table->string('market', 30)->change();   // проще уйти от enum, чем плодить ALTER
});
```

Если хватает нового `selection` внутри существующего рынка (например, `totals`
с линией 1.5 или 3.5) — миграция не нужна вообще, `selection` уже строка.

### 2. Вероятность по модели

`MethodEstimator` считает распределение методов победы и тотал 2.5.
Новую оценку добавляйте туда же и возвращайте её в массиве `estimate()`.

Если рынок требует новой колонки в `predictions` — добавьте миграцию, каст
в модели `Prediction` и поле в `PredictionResult::toArray()`.

Держите инвариант: вероятности внутри одного набора исходов должны давать
в сумме 1.0. Тест на это уже есть, добавьте свой для нового набора.

### 3. Сопоставление котировки с вероятностью

`BettingService::probabilityForMarket()` — единственное место, где рынок букмекера
превращается в вероятность модели. Не добавите ветку — котировка просто
проигнорируется, без ошибки:

```php
$odd->market === 'totals' && $odd->selection === 'over' && (float) $odd->line === 1.5
    => $prediction->probability_over_1_5,
```

Обратите внимание на сравнение `line`: она приходит как `float` из каста,
сравнивайте после явного приведения.

### 4. Загрузка котировок от поставщика

`TheOddsApiProvider::mapOutcome()` переводит рынки The Odds API в наши.
Ключи API: `h2h`, `totals`, `spreads`. Если рынка там нет — котировку придётся
вводить вручную, и это нормально.

Для ручного ввода расширьте:

- валидацию в `FightController::storeOdds()` (правила `odds.*.market`, `odds.*.selection`);
- форму в `frontend/src/views/FightView.vue` — объект `manualOdds` и вызовы `push()`
  в методе `saveOdds()`.

### 5. Расчёт результата — самое важное

`BankrollService::outcomeFor()` определяет исход ставки: `won`, `lost` или `void`.
Добавьте ветку в `match ($bet->market)` и отдельный приватный метод, как сделано
для `totalsOutcome()` и `methodOutcome()`.

Правила, которых держится проект:

- бой признан несостоявшимся (`is_no_contest`) — **всегда возврат**, до всех прочих проверок;
- ничья на рынке победы — возврат, а не проигрыш;
- точное попадание в линию тотала — возврат (`push`);
- если данных для расчёта не хватает (нет метода, нет раунда) — возврат, а не проигрыш;
  проиграть ставку из-за неполных данных нельзя.

Полное время боя в секундах: `total_seconds`, либо `(end_round - 1) * 300 + end_time_seconds`.
Тотал «больше 2.5» выигрывает при времени строго больше 750 секунд.

### 6. Подписи в интерфейсе

`frontend/src/utils/format.js`:

- `MARKET_LABELS` — название рынка;
- `SELECTION_LABELS` — название исхода;
- `selectionLabel()` — если исход должен показываться именем бойца или с числом линии.

Ещё одно место — `OddsQuote::label()` в бекенде: оттуда берётся текст пояснения
к рекомендации («Тотал раундов меньше 2.5: модель даёт 58%…»), который пользователь
видит в таблице ставок.

И `selectionName()` в `frontend/src/views/FightView.vue` — таблица котировок на странице боя.

### 7. Тесты

Обязательный минимум в `tests/Feature/BetSettlementTest.php`:

```php
public function test_new_market_settles_correctly(): void
{
    $service = app(BankrollService::class);
    $bet = $this->bet(['market' => 'ваш_рынок', 'selection' => 'ваш_исход']);

    $result = Result::create([...]);

    $this->assertSame('won', $service->outcomeFor($bet, $this->fight, $result));
}
```

Покройте три случая: выигрыш, проигрыш и возврат (NC либо нехватка данных).
Если добавили вероятность — тест нормировки в `tests/Unit/PredictionEngineTest.php`.

## Проверка целиком

```bash
make test
make fresh                # пересоздать базу с демо-данными
make predict              # рекомендации должны включить новый рынок
```

Затем откройте бой в интерфейсе: новый рынок должен появиться в таблице котировок
с вероятностью модели, а при наличии value — в таблице ставок. Введите результат
вручную и убедитесь, что ставка перешла в «выигрыш» или «проигрыш», а не осталась
в «размещена».

## Про лимиты

Новый рынок не отменяет ограничение «суммарно не более 10% банка на один бой»
(`config/ufc.php` → `bankroll.max_fraction_per_fight`). `BankrollCalculator::evaluateFight()`
разложит лимит по рынкам сам, в порядке убывания EV, и урежет последнюю ставку
до остатка. Ничего дополнительно делать не нужно — но и обходить это нельзя.
