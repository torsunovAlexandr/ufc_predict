# AGENTS.md — как работать с этим проектом

Читается перед любой правкой: и человеком, и ассистентом.
Порядок чтения для новой сессии: **`docs/session-context.md` → этот файл →
`docs/roadmap-v2.md` → ТЗ текущего этапа в `docs/stage-N.md`.**

---

## Где проект находится сейчас

Проект переписывается с нуля. Сделан **этап 0** — каркас и конвейер проверок.
Предметной логики в репозитории нет ни строки: ни модели прогноза, ни ставок,
ни парсеров, ни предметных таблиц. Всё это появляется поэтапно,
начиная с этапа 1.

`docs/session-context.md` всегда содержит актуальный ответ на вопрос
«что дальше» — он обновляется в конце каждого этапа.

## Порядок работы

Он согласован с владельцем проекта и не меняется по ходу.

1. **Один этап за раз.** Этапы описаны в `docs/roadmap-v2.md`, часть 5.
2. **Код исполняется и проверяется до передачи.** Не «должно работать», а
   «запущено, вот вывод». Пять дефектов из двенадцати в первой версии
   появились ровно потому, что код ни разу не был запущен.
3. **На каждый этап пишется ТЗ и тест-план** — образец `docs/stage-0.md`,
   раздел 0.7. Тест-план это таблица «команда → что вы должны увидеть».
4. **Один этап — один pull request** с зелёным CI. Ветка `main` защищена,
   прямой пуш запрещён.
5. **Следующий этап не начинается без явного слова владельца.**

## Правила, которые нельзя нарушать

### 1. Стрелки зависимостей только снизу вверх

```
Domain          чистый PHP, ноль зависимостей: математика и правила
Application     сценарии, оркестрация, порты
Infrastructure  адаптеры: БД, HTTP-источники, файлы
Interface       REST API, artisan-команды, планировщик, фронтенд
```

Domain не знает ни о Laravel, ни о базе, ни о HTTP. Это единственная часть
первой версии, которая ни разу не сломалась, — приём сохраняется.

### 2. У каждого внешнего источника есть порт и три адаптера

Живой источник, **фикстура** (на ней пишутся тесты) и **ручной ввод**.
Система обязана оставаться работоспособной, когда все парсеры сломаны.

### 3. Генераторы конфигов только дописывают

Никогда не перезаписывают. Порты, пути и имена записываются в конфигурацию
пользователя один раз при первой настройке и после этого не меняются —
даже если в репозитории поменялось умолчание. Это дефекты №6 и №7.

### 4. Разовая команда в контейнере исполняется молча

`docker compose exec php php -v` обязан выдать ровно вывод `php -v`.
Этот вывод разбирает PhpStorm, определяя интерпретер. `docker/php/entrypoint.sh`
различает роли и печатает подготовку только для php-fpm и планировщика.
Проверяется автоматически в сборке `stack`. Это дефект №9.

### 5. Все числа модели — в одном конфиге

Веса, пороги, коэффициенты не разбросаны по классам. Появится вместе
с моделью на этапе 1.

### 6. Никаких одноимённых колонок в связываемых таблицах

`fights.status` и `events.status` дали 500 на дашборде — дефект №3.
В v2 это `fights.bout_status` и `events.event_status`.

### 7. Интерфейс, комментарии и документация — по-русски

Идентификаторы в коде — по-английски, как принято в PHP.

## Как проверять работу

Перед тем как сказать «готово»:

```bash
make check     # Pint + PHPStan + PHPUnit — то же, что гоняет сборка backend
make doctor    # восемь проверок живой системы
```

Сборку `stack` целиком воспроизвести без Docker нельзя — она проверяется
в GitHub Actions на каждый pull request. Именно она ловит дефекты №2, №8 и №9.

### Что обязательно покрывается тестами

- вся математика Domain — в наборе `Unit`, без Laravel и без базы;
- каждый эндпоинт API — в наборе `Feature`, на SQLite в памяти;
- каждый адаптер внешнего источника — на фикстуре, а не на живом сайте;
- каждый исправленный дефект — тестом, который падал бы до исправления.

Тесты обоих наборов обязаны проходить там, где нет ни MySQL, ни сети.

## Чего делать не нужно

- Начинать следующий этап, не дождавшись слова владельца.
- Добавлять в `Makefile` команду, под которой ещё нет работающего кода:
  команда, падающая с «command not found», ничем не лучше отсутствующей.
- Менять умолчание порта, пути или имени под уже настроенной системой.
- Класть `frontend/dist`, `vendor/` или `.env` в git.
- Трогать `docs/requirements.md` — это исходное ТЗ, оно не меняется.
- Писать `default-authentication-plugin` в `docker/mysql/my.cnf`: переменная
  удалена в MySQL 8.4, контейнер уйдёт в цикл перезапуска (дефект №2).
- Полагаться на то, что внешний формат данных остался прежним. Для этого
  есть сборка `contract`, которая ходит к источникам по расписанию.

## Двенадцать дефектов первой версии

Полный разбор с причинами — `docs/roadmap-v2.md`, часть 1. Коротко:

| № | Что сломалось | Чем закрыт |
|---|---|---|
| 1 | Laravel вне окна поддержки | версия сверена с релизной страницей, `composer install` в CI |
| 2 | MySQL падал из-за удалённой переменной | сборка `stack`: контейнер обязан стать healthy |
| 3 | неоднозначная колонка `status` в join | переименование колонок, этап 2 |
| 4 | тест требовал непредставимого в double | набор `Unit` действительно запускается |
| 5 | порт базы наружу не описан | `make db-info`, `make doctor` |
| 6 | смена умолчания порта | порт пишется явно и не меняется |
| 7 | `make env` перезаписывал `.env` | генератор только дописывает |
| 8 | `make debug-on` не пересобирал образ | `make debug-check` + проверка в `stack` |
| 9 | entrypoint шумел в stdout | автопроверка первой строки `php -v` |
| 10 | ничья маппилась в `moneyline` | этап 4, на фикстурах |
| 11 | тотал 4.5 не поддерживался | произвольная линия тотала, этап 2 |
| 12 | котировки сопоставлялись с одним турниром | этап 4 |

Дефекты 1, 2, 5, 6, 7, 8, 9 закрыты этапом 0 механически — так, что
повторить их можно только сознательно, сломав проверку.
