## Что нашлось при доведении сборок до зелёного

Три дефекта, которых не показала ни одна локальная проверка. Подробный разбор —
в комментарии к [PR #1](https://github.com/torsunovAlexandr/ufc_predict/pull/1);
здесь коротко, потому что все три — про способ рассуждать, а не про частный баг.

**1. `php-fpm` отвечал 500 при живых контейнерах.** `storage` и `bootstrap/cache`
приходят из bind-mount и на Linux сохраняют владельца с хост-машины, а запросы
обслуживает `www-data`. Blade не мог записать скомпилированный шаблон. Планировщик
работал, потому что выполняется из-под root, — и создавал впечатление, что
приложение в порядке. **На macOS этого не видно вообще**: Docker Desktop подменяет
владельца файлов в bind-mount. Исправлено `chown` в `docker/php/entrypoint.sh`.

**2. Проверка Xdebug не проверяла ничего.** `ini_get("xdebug.mode")` возвращает
пустую строку и при включённом отладчике, и при выключенном: режим задаётся
переменной окружения `XDEBUG_MODE` мимо ini-значения. Проверено экспериментально
на собранном из исходников Xdebug. Действующий режим знает только
`xdebug_info("mode")`.

**3. `ufc.com` отвечает 403 на адреса датацентров.** Проверено из GitHub Actions
и ещё двух облачных сред; браузерный User-Agent не помогает. Проверка разделена
по месту запуска: `contract` засчитывает 200 и 403 (её дело — что имя резолвится,
TLS встаёт, сервер отвечает), а восьмая проверка `make doctor` смотрит на сайт
с машины разработчика. **Вывод для этапа 3: сбор турниров нельзя переносить
в облако, он живёт там же, где приложение.**

## Как эта сессия работает с GitHub

Важное отличие от предыдущей сессии: **работать надо не из контейнера Claude,
а из Linux-VM на Маке** (инструмент `device_bash`).

| Среда | GitHub |
|---|---|
| Контейнер Claude | `api.github.com` для этого репозитория отдаёт 403 от прокси песочницы. `git ls-remote` по токену при этом работает, а API и пуш — нет |
| Linux-VM на Маке (`device_bash`) | **полный доступ**: `api.github.com` 200 по токену, `git push` проходит. Здесь и делается всё: пуш, PR, ruleset |

Порядок, который сработал: склонировать репозиторий в `$HOME/work` внутри VM
(вне `mnt/`, потому что в `mnt/` git не может удалять файлы), работать там,
пушить оттуда.

### Чего нельзя

**Скачать журнал прогона Actions нельзя ни из одной среды:** API отдаёт 302 на
`productionresultssa9.blob.core.windows.net`, а этот адрес закрыт и в контейнере,
и в VM. Читать падения так:

1. `GET /actions/runs/{id}/jobs` — какой шаг упал (это по API доступно);
2. страница прогона в браузере Claude (`Claude_Browser__preview_start`) — там
   видны **аннотации** и **сводка прогона** (job summary).

Поэтому сборка `stack` пишет диагностику падения в `$GITHUB_STEP_SUMMARY`:
состояние контейнеров, хвост журналов и тело ответа `/up`, если он вернул не 200.
Без этого падение выглядит как «приложение просто не отвечает».

**Токен PAT не даёт доступа к Checks API** («Resource not accessible by personal
access token») — сводку прогона через `/check-runs` не прочитать, только глазами
в браузере.

### Доступ

- Репозиторий: `https://github.com/torsunovAlexandr/ufc_predict.git` (публичный).
- Токен с правами на репозиторий — `.secrets/gh-token` в папке проекта.
  Каталог `.secrets/` в `.gitignore` — не коммитить, не печатать содержимое в чат.
- Правило защиты `main` (ruleset id 21807764): только через pull request,
  обязательные проверки `backend`, `frontend`, `stack`, без force-push и удаления.
  `contract` в обязательные не включена намеренно: она запускается не на каждый PR,
  и требование её прохождения блокировало бы вливание.

## Инструменты

**Контейнер Claude:** `php 8.4.21`, `composer`, `node 22.22.2`, `npm 10.9.7`, `git`.
`gh` нет — pull request и ruleset делаются через REST API.
Composer не может скачивать dist-архивы (`codeload.github.com` — 403 от прокси),
установка идёт через `--prefer-source`. В GitHub Actions этой проблемы нет.

**Linux-VM на Маке:** `git`, `curl`, `python3`, сеть до GitHub. PHP и Node там нет.

**Docker-демона нет нигде** — ни в контейнере, ни в VM. Сборка `stack` проверяется
только в GitHub Actions. Это не мелкое неудобство: все три дефекта выше нашлись
именно там и только там.
