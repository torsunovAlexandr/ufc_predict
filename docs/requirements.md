# Техническое задание на разработку системы прогнозирования боёв UFC и виртуальных ставок

## 1. Общее описание системы

Разрабатывается веб-приложение, которое автоматически собирает статистику бойцов UFC, прогнозирует исходы предстоящих боёв на основе гибридной экспертно-статистической модели, даёт рекомендации по ставкам (исход и сумма) с целью максимизации виртуальной прибыли, а также ведёт подробную статистику виртуального банкролла.

Приложение предназначено для персонального использования одним пользователем (или небольшой группой) и не предполагает публичного доступа.

**Ключевые функции:**
- Автоматическое получение списка предстоящих турниров и кардов боёв.
- Сбор и обновление статистики бойцов из открытых источников (прежде всего официальный сайт UFC).
- Расчёт вероятностей исходов боёв на основе гибридной модели.
- Получение актуальных букмекерских коэффициентов (через API или парсинг).
- Генерация рекомендаций: на какой исход ставить и какую сумму (в виртуальных рублях).
- После завершения турнира – получение фактических результатов, расчёт прибыли/убытка, обновление банкролла.
- Отображение подробной статистики: общий профит, ROI, процент выигрышных ставок, график изменения банка, история прогнозов.
- Личный кабинет с настройками (стартовый банкролл, лимиты, тема оформления).

## 2. Источники данных и сбор информации

### 2.1. Статистика бойцов и события
- **Основной источник:** официальный сайт UFC (www.ufc.com) и связанные публичные страницы.
- **Дополнительные источники:** при необходимости – Sherdog, ESPN, Wikipedia (для уточнения рекордов, возраста, размаха рук).
- **Метод получения:** парсинг HTML страниц (с использованием библиотек типа Guzzle + Symfony DomCrawler в PHP) или, если доступен, неофициальный API.
- **Автоматическое обновление:** перед каждым турниром система должна проверять наличие новых боёв и обновлять статистику участвующих бойцов. Частота обновления: не чаще одного раза в 3 часа для одного источника.
- **Кэширование:** все полученные данные сохраняются в БД, повторные запросы к одним и тем же страницам не выполняются чаще, чем раз в 24 часа (если данные не изменились).

### 2.2. Букмекерские коэффициенты
- **Источник:** букмекерские конторы, предоставляющие API (например, The Odds API, Betfair, 1xBet) или парсинг сайтов. Предпочтителен API с бесплатным тарифом.
- **Ограничения:** не более 500 запросов в день; для парсинга – не чаще 1 запроса в 10 минут на конкретный сайт.
- **Обновление:** коэффициенты запрашиваются непосредственно перед формированием рекомендаций (за 1–2 дня до боя и в день боя).

### 2.3. Результаты боёв
- **Метод:** после завершения турнира пользователь нажимает кнопку «Получить актуальные результаты». Система автоматически ищет результаты через поисковые запросы (Google, Bing) или парсит официальный сайт UFC, новостные порталы (MMA Fighting, Sherdog).
- **Ограничения:** не более 5 запросов в минуту; уважать robots.txt; при невозможности автоматического получения предусмотреть ручной ввод результатов.

## 3. Хранение данных

- **СУБД:** MySQL 8+.
- **Структура БД** (основные таблицы):
    - `fighters` – данные бойцов (имя, возраст, рост, размах рук, стойка, рекорд, стиль, статистика по карьере: средние тейкдауны, защита, удары и т.д.).
    - `events` – турниры (название, дата, место, высота над уровнем моря).
    - `fights` – бои (связь с событием, бойцы, весовая категория, количество раундов, титульный/не титульный).
    - `fighter_stats` – детальная статистика по каждому бою (тейкдауны, попытки, защита, значимые удары, сабмишены, контроль времени, кардио-показатели).
    - `odds` – коэффициенты на различные исходы (победа бойца 1, победа бойца 2, ничья, тотал раундов, метод победы) с указанием букмекера и времени получения.
    - `predictions` – прогнозы системы (бой, вероятности исходов, рекомендованная ставка, сумма, коэффициент, уверенность, объяснение).
    - `bets` – фактически сделанные виртуальные ставки (на основе прогнозов).
    - `results` – фактические результаты боёв.
    - `bankroll_history` – история изменения банкролла.
    - `settings` – настройки пользователя.

## 4. Алгоритм прогнозирования (гибридная система)

### 4.1. Сбор и подготовка параметров бойцов
Для каждого бойца вычисляются следующие показатели (на основе последних 5–10 боёв, с учётом уровня соперников):

**Атакующие:**
- Среднее количество тейкдаунов за бой.
- Точность тейкдаунов (%).
- Среднее количество значимых ударов в минуту.
- Точность значимых ударов (%).
- Среднее количество попыток сабмишенов за бой.
- Процент досрочных побед.

**Защитные:**
- Защита от тейкдаунов (%).
- Защита от значимых ударов (%).
- Способность избегать сабмишенов (на основе поражений сабмишенами).

**Физические и контекстные:**
- Возраст, рост, размах рук.
- Стойка (левша/правша/универсал).
- Рекорд (общий, в UFC, последние 5 боёв).
- Стиль: борец, ударник, универсал (классификация на основе статистики).
- Кардио (падение эффективности в поздних раундах: сравниваются показатели 1–2 раунда и 3+ раундов).
- Опыт 5-раундовых боёв.

### 4.2. Учёт контекста боя
- Весовая категория (влияет на важность физических данных).
- Количество раундов (3 или 5) – для 5-раундовых боёв выше значимость кардио и опыта длинных боёв.
- Титульный бой – повышает мотивацию, но может влиять на осторожность.
- Место проведения (высота над уровнем моря – фактор выносливости).
- Личная встреча: если бойцы уже встречались, результат прошлого боя корректирует вероятности (с weighting 0.15).

### 4.3. Гибридная модель расчёта вероятностей
Модель сочетает статистическое сравнение с экспертными правилами.

**Шаг 1. Сравнение по каждому параметру.**  
Для каждого показателя (например, тейкдауны за бой) вычисляется относительное преимущество одного бойца над другим по формуле:  
`advantage = (value_f1 - value_f2) / (value_f1 + value_f2 + epsilon)`.  
Значение нормализуется в диапазон [-1, 1].

**Шаг 2. Применение весов.**  
Каждому показателю присваивается вес, отражающий его важность для победы (определяется экспертно и может настраиваться). Примеры весов:
- Тейкдауны (атака) – 0.20
- Защита от тейкдаунов – 0.15
- Значимые удары (атака) – 0.25
- Защита от ударов – 0.10
- Сабмишены (атака) – 0.10
- Защита от сабмишенов – 0.05
- Кардио – 0.10
- Опыт/возраст/физика – 0.05

Сумма весов = 1.0.

**Шаг 3. Экспертные правила (корректировка).**
- Если борец (тейкдауны > 3 за бой) встречается с бойцом с плохой защитой от тейкдаунов (< 50%) и слабым грепплингом, то вероятность победы борца повышается на 5–10%.
- Если ударник с хорошей защитой от тейкдаунов (> 70%) против борца – вероятность ударника повышается.
- Если боец левша, а соперник правша (и наоборот) – небольшая корректировка (2–3%) в пользу левши (неудобство).
- Возраст: разница более 5 лет в пользу молодого бойца (если ему до 35) – +3%.
- Если боец проиграл последние 2 боя нокаутом – его вероятность снижается на 5%.
- Если бой 5-раундовый, а боец никогда не дрался 5 раундов, его вероятность снижается на 4%.

**Шаг 4. Итоговый расчёт.**  
Для каждого бойца вычисляется взвешенная сумма преимуществ и применяются экспертные корректировки. Затем через сигмоидальную функцию получаем вероятность победы:  
`P1 = 1 / (1 + exp(-score1))`, `P2 = 1 - P1`.

Дополнительно оцениваются вероятности методов победы (решение, нокаут, сабмишен) на основе статистики досрочных побед и стилей. Это необходимо для сравнения с коэффициентами на соответствующие рынки.

### 4.4. Объяснение прогноза
Система формирует текстовое объяснение: перечисляются ключевые факторы, повлиявшие на прогноз (например: «Боец А имеет значительное преимущество в борьбе (4.2 тейкдауна за бой против 1.1 у соперника) и высокую защиту от тейкдаунов (80%), что должно нейтрализовать сильную сторону Бойца Б. Однако у Бойца Б лучше кардио и опыт 5-раундовых боёв. Итоговая вероятность победы Бойца А – 63%»).

## 5. Система ставок и управление банкроллом

### 5.1. Начальные условия
- Стартовый виртуальный банкролл: **10 000 рублей** (может быть изменён в настройках).
- Валюта: российский рубль (₽).

### 5.2. Получение коэффициентов
Система запрашивает коэффициенты на следующие рынки (если доступны):
- Победа бойца 1 (Moneyline).
- Победа бойца 2.
- Ничья (если есть).
- Тотал раундов (больше/меньше 2.5).
- Метод победы (нокаут/технический нокаут, сабмишен, решение).

### 5.3. Поиск value-ставок
Для каждого исхода система сравнивает собственную оценку вероятности `P` с букмекерским коэффициентом `K`.  
Вычисляется expected value (EV):  
`EV = P * K - 1`.

Если `EV > 0.05` (порог настраивается), ставка считается value и рекомендуется.

### 5.4. Определение суммы ставки
Используется модифицированный критерий Келли с ограничениями.

Формула доли банка:  
`f = (P * K - 1) / (K - 1)`.

Затем применяются корректировки:
- Коэффициент уверенности: если вероятность по модели выше 0.65, умножаем f на 1.2; если ниже 0.55 – на 0.8.
- Ограничение максимальной доли: `f_max = 0.05` (5% банка) для стандартных ставок, но при высокой уверенности (P > 0.8) может быть до 10%.
- Ограничение минимальной доли: если рассчитанная f < 0.005, ставка не рекомендуется.
- Округление суммы до целых рублей.

Сумма ставки = `bankroll * f`.

### 5.5. Учёт нескольких ставок на один бой
Если найдено несколько value-исходов (например, победа бойца и тотал меньше), система может рекомендовать несколько ставок, но суммарная доля банка не должна превышать 10% на один бой. Приоритет отдаётся ставке с наибольшим EV.

## 6. Статистика виртуального заработка

### 6.1. Отслеживаемые метрики
- Общий профит (сумма выигрышей минус сумма ставок).
- ROI = (профит / сумма всех ставок) * 100%.
- Процент выигранных ставок.
- Текущий банкролл.
- Серия прибыльных/убыточных ставок.
- Количество ставок, средняя сумма ставки, средний коэффициент.
- График изменения банкролла во времени.

### 6.2. Хранение истории
Каждая рекомендация и фактически сделанная ставка сохраняются в БД. При получении результатов система автоматически рассчитывает выигрыш/проигрыш и обновляет банкролл.

### 6.3. Сравнение с бенчмарками
В статистике предусмотрен раздел сравнения:
- Случайный выбор победителя (50/50).
- Ставки на фаворита по коэффициентам (всегда ставка на меньший коэффициент).
  Это позволяет оценить, превосходит ли система простые стратегии.

## 7. Пользовательский интерфейс

### 7.1. Технологии
- **Фронтенд:** Vue.js 3 (с Vite), Pinia для состояния, Vue Router, Axios для API.
- **Бекенд:** PHP 8.2+ (рекомендуется Laravel 10 или Slim 4) с REST API.
- **База данных:** MySQL 8.
- **Деплой:** Docker, docker-compose (контейнеры: nginx, php-fpm, mysql, node для сборки фронта).

### 7.2. Основные страницы
- **Дашборд:** текущий банкролл, ближайшие бои с краткими прогнозами, последние результаты.
- **Предстоящие события:** список турниров и боёв, при клике на бой – детальный прогноз с объяснением, коэффициентами и рекомендуемой ставкой.
- **Статистика:** графики (использовать Chart.js), таблицы с историей ставок, фильтры по датам, турнирам, бойцам.
- **Настройки:** стартовый банкролл, порог value, максимальный процент ставки, тема оформления.
- **История боёв:** прошедшие бои с результатами и сравнением прогноза с фактом.

### 7.3. Локализация и темы
- Язык интерфейса: только русский.
- Поддержка светлой и тёмной темы (переключение в настройках, сохранение выбора).

## 8. Интеграции и внешние API

- **UFC данные:** парсинг официального сайта (HTML) – реализовать через Guzzle + DomCrawler, соблюдая задержки.
- **Коэффициенты:** использовать API агрегатора коэффициентов (например, The Odds API) с бесплатным ключом; fallback – парсинг сайта БК (например, Марафон, 1xBet) с ограничениями.
- **Результаты:** парсинг новостных сайтов или поиск через Google Custom Search API (бесплатный лимит 100 запросов/день). При недоступности – ручной ввод.
- **Ограничения:** все запросы кэшируются, частота запросов не превышает установленных лимитов (см. раздел 2).

## 9. Тестирование

- **Бэктестинг:** на исторических данных (прошедшие турниры за последние 2 года) проверяется точность прогнозов и прибыльность стратегии. Для этого используется накопленная статистика.
- **Live-тестирование:** система будет использоваться на реальных предстоящих событиях, с фиксацией всех рекомендаций и результатов.
- **Юнит-тесты:** для ключевых компонентов (расчёт вероятностей, критерий Келли, парсеры).

## 10. Использование Claude в разработке

- Claude будет использоваться для генерации кода (шаблоны, реализация отдельных модулей) по запросам разработчика.
- Не требуется интеграция Claude в рантайм приложения.
- Все сгенерированные фрагменты кода должны быть проверены и адаптированы под конкретную архитектуру.
