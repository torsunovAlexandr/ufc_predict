# UFC Predict

Прогнозирование исходов боёв UFC и виртуальные ставки на банкролл.
Исходные требования к продукту — [`docs/requirements.md`](docs/requirements.md).

> **Проект переписывается с нуля.**
> Первая версия дала двенадцать дефектов; их разбор и деление работы
> на одиннадцать этапов — в [`docs/roadmap-v2.md`](docs/roadmap-v2.md).
> Сейчас сделан **этап 0**: каркас и конвейер проверок.
> Предметной логики в репозитории нет — она появляется с этапа 1.

## Что уже есть

| | |
|---|---|
| Бекенд | Laravel 13 на PHP 8.4. Один эндпоинт: `GET /api/health` |

статистики. Всё это расписано по этапам в `docs/roadmap-v2.md`, часть 5.

## Быстрый старт

Нужен только Docker — Docker Desktop или OrbStack. PHP, composer и node
на вашей машине не требуются: всё живёт в контейнерах.

```bash
git clone https://github.com/torsunovAlexandr/ufc_predict.git "ufc predict"
cd "ufc predict"
make setup
```

Первый запуск занимает пару минут: composer ставит зависимости, node собирает
фронтенд, MySQL создаёт базу. Дальше:

```bash
make doctor
```

Семь проверок. Если все зелёные — приложение открывается
на <http://localhost:8080>, а внизу вывода напечатаны параметры подключения
к базе для PhpStorm.

`make` без аргументов покажет полный список команд.

## Два файла `.env` — зачем

Это самое частое место, где путаются.

| Файл | Кто читает | Что там |
|---|---|---|
| `.env` в корне | `docker compose` | порты **на вашей машине**: `APP_PORT`, `DB_PORT_EXTERNAL` |
| `backend/.env` | Laravel | параметры **внутри docker-сети**: `DB_HOST=mysql`, `DB_PORT=3306` |

Оба создаются командой `make setup` из файлов `.env.example`, оба не входят
в репозиторий. `DB_PORT=3306` в `backend/.env` — это порт внутри сети,
а `DB_PORT_EXTERNAL=33061` в корневом `.env` — тот, по которому к базе
подключается PhpStorm. Снаружи имя `mysql` не резолвится, нужен `127.0.0.1`.

**Генератор `.env` только дописывает недостающие ключи.** Правьте эти файлы
руками сколько угодно: повторный `make setup` ничего не перезапишет.
Однажды перезапись стёрла настроенное подключение — так появился дефект №7,
и теперь это невозможно по построению.

## Подключение к базе из PhpStorm

```bash
make db-info
```

Печатает хост, порт, базу, логин и пароль. То же самое печатает `make doctor`
после успешной проверки.

Порт снаружи — **33061**, а не 3306: 3306 обычно занят локально установленным
MySQL. Значение записано явным числом в корневой `.env` и после первой
настройки не меняется.

## Отладка через Xdebug

Xdebug присутствует в образе всегда, а включается переменной окружения:

```bash
make debug-on     # пересобирает образ, поднимает контейнеры, сразу проверяет
make debug-check  # показать, установлен ли Xdebug и в каком он режиме
make debug-off
```

Порт 9003, IDE key `PHPSTORM`, старт по триггеру.
Пошаговая настройка PhpStorm — [`docs/phpstorm-xdebug.md`](docs/phpstorm-xdebug.md).

## Фронтенд

```bash
make front        # собрать в frontend/dist
make front-dev    # vite с горячей перезагрузкой на http://localhost:5173
```

`frontend/dist` **не хранится в git**. Собранные файлы рядом с исходниками
приводят к тому, что рассинхрон сборки замечается поздно; `make doctor`
отдельно проверяет, что сборка не старше `frontend/src`.

## Проверки

```bash
make test          # все тесты бекенда в контейнере
make test-unit     # только Unit — без Laravel и без базы
make test-feature  # Feature — приложение на SQLite в памяти
make lint          # оформление кода (Pint)
make analyse       # статический анализ (PHPStan + Larastan, уровень 6)
make check         # всё перечисленное одной командой — то же, что гоняет CI
```

В GitHub Actions четыре сборки:

| Сборка | Когда | Что делает |
|---|---|---|
| `backend` | push, pull request | composer, Pint, PHPStan, PHPUnit на SQLite |
| `frontend` | push, pull request | `npm ci`, `npm run build` |
| `stack` | push, pull request | поднимает весь Compose с нуля и проверяет систему целиком |
| `contract` | ежедневно | доступность внешних источников данных |

Главная — `stack`. Она ловит те дефекты инфраструктуры, которые в первой
версии обнаруживались только вручную и с опозданием.

## Если что-то не поднялось

Сначала `make doctor` — он называет причину и подсказывает команду.
Дальше по порядку:

```bash
make ps                          # что вообще запущено
docker compose logs mysql | tail -30
make logs                        # логи бекенда
make reset && make setup         # снести базу и настроить заново
```

Строка `unknown variable` в логах MySQL означает, что в `docker/mysql/my.cnf`
попал ключ, удалённый в MySQL 8.4. Так выглядел дефект №2; в файле на этот счёт
стоит предупреждение.
